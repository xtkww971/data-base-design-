> 임계값 주의: `application.yml` 의 기본값(`0.65`)은 도커에서 쓰이지 않는다. `docker-compose.yml` 이
> `TYPESAFE_CONFIDENCE_THRESHOLD` 를 넣기 때문이다(기본 0.7). 그래서 `.env` 에 `0.65` 를 넣었다.
> 실행기가 `meta.json` 에 **컨테이너 안의 실제 값**을 남기므로 실행 전후에 확인한다.

### 거절 규칙

```
verdict ∈ {answerable, recommendation}         → 진행
verdict ∈ {out_of_scope, missing_data, ambiguous}
    confidence ≥ 0.65                          → 422 거절
    confidence < 0.65                          → 진행
판정 실패 · 타임아웃                             → 진행 (fail-open)
```

## 4. 진행 방법

```bash
# 1) .env 의 GROQ_API_KEY 를 새 키로 바꾼 뒤, 바뀐 환경변수로 컨테이너를 다시 만든다
docker compose up -d --force-recreate backend nl2sql

# 2) 컨테이너 안의 임계값 확인 (0.65 여야 한다)
docker exec dbd-backend sh -c 'echo $TYPESAFE_CONFIDENCE_THRESHOLD'

# 3) 실행 (저장소 루트)
python tools/nl2sql_eval.py "docs/test/test 2/test_2_questions.json"
```

- 결과: `docs/test/test 2/runs/<실행 시각>/` (`meta.json`, `results.jsonl`, `results.csv`, `report.md`)
- 실행 중에는 같은 백엔드로 다른 질문을 보내지 않는다.
- LLM 한도에 걸리면 실행기가 멈추고 이어 돌릴 명령을 출력한다. 그때는
  `python tools/nl2sql_eval.py --drop-rate-limited "<실행 폴더>"` 로 무효 기록을 옮긴 뒤 출력된 명령으로 이어 돌린다.
- 토큰 예상: 생성까지 가는 질문 약 34개 × 평균 1.3회 시도 × 약 3천 토큰 ≈ **13만 토큰**.
  새 키의 하루 한도가 20만이면 다른 사용과 겹치지 않는 한 충분하다.

1. 임계값 0.65 를 유지할지, 0.7 로 되돌릴지, 판정별로 다르게 둘지(예: ambiguous 만 따로).
