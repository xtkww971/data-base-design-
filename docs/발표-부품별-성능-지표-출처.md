## 1. 지표를 고른 기준

1. **공신력**: 업계에서 널리 쓰는 공개 벤치마크를 우선한다.
2. **일관성**: 한 카테고리의 모든 제품을 같은 척도로 잴 수 있어야 한다.
3. **재현성**: 누구나 출처 링크나 공식으로 같은 값을 다시 얻을 수 있어야 한다.
4. **출처 없는 값은 넣지 않는다**: 근거가 없으면 NULL로 둔다 (메인보드).

## 2. CPU · GPU · 저장장치: PassMark

| 부품 | 지표 | 측정 내용 |
| --- | --- | --- |
| CPU | CPU Mark | 정수·부동소수·압축·암호화 등을 섞은 멀티스레드 종합 점수 |
| GPU | G3D Mark | DirectX 9~12 3D 렌더링 종합 점수 |
| SSD/HDD | Disk Rating | 순차 읽기/쓰기, 랜덤 IOPS를 합친 종합 점수 |

**PassMark를 쓴 이유**
- CPU, GPU, 저장장치를 **한 기관의 방식**으로 모두 제공한다.
- 수백만 건의 사용자 제출 결과를 평균하므로 표본이 크다.
- 제품별 페이지가 공개되어 있어 바로 검증할 수 있다.
- SSD와 HDD가 **같은 척도**라 저장장치 전체를 한 번에 비교할 수 있다.

**예시 값**

| 제품 | 점수 |
| --- | ---: |
| 인텔 코어 i7-14700K | 51,906 |
| AMD 라이젠7 7800X3D | 34,278 |
| GeForce RTX 4080 SUPER | 34,212 |
| GeForce RTX 4060 | 19,478 |
| WD Black SN850X 2TB (NVMe SSD) | 51,176 |
| 삼성 870 EVO 500GB (SATA SSD) | 4,177 |
| Seagate BarraCuda 2TB (HDD) | 2,375 |

**한계**
- 사용자가 제출한 결과의 평균이라 **시간이 지나면 값이 조금씩 바뀐다.**
- CPU Mark는 멀티스레드 위주라서 **게임 성능 순위와 다를 수 있다.**
  예를 들어 게임용으로 유명한 7800X3D가 14600K(38,349)보다 낮게 나온다.
- 표본이 적은 제품은 편차가 크다. WD Red Plus 8TB는 표본이 1건이다.

## 3. RAM: 이론 메모리 대역폭

```
점수(MB/s) = 클럭(MT/s) × 8 Byte × 채널 수
채널 수   = min(모듈 개수, 2)
```

- DIMM 한 장의 데이터 버스는 64bit(8Byte)이고, JEDEC DDR4/DDR5 규격 공통이다.
- 듀얼 채널(모듈 2개)이면 대역폭이 2배가 된다.

| 예시 | 계산 | 점수 |
| --- | --- | ---: |
| DDR4-3200 ×1 | 3200 × 8 × 1 | 25,600 |
| DDR5-6000 ×2 | 6000 × 8 × 2 | 96,000 |

**RAM에 외부 벤치마크를 쓰지 않은 이유:** 공신력 있는 제품별 벤치마크가 없고,
실제 성능은 CPU와 메인보드 조합에 따라 크게 달라진다.

**한계:** CL(레이턴시)과 용량은 반영하지 않는다.

## 4. 파워: 80 PLUS 효율 등급

80 PLUS 인증(115V Internal 기준)에서 **50% 부하일 때 보장하는 최소 효율**을 점수로 쓴다.

| 등급 | STANDARD | BRONZE | SILVER | GOLD | PLATINUM | TITANIUM |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 점수(%) | 80 | 85 | 88 | 90 | 92 | 94 |

- 인증 기관: CLEAResult (80 PLUS 프로그램 운영)
- 파워 용량(W)은 이미 `power.rated_power` 컬럼에 있어서 점수에서 뺐다.

**한계:** 같은 등급이면 점수가 같다. 제품별 실측 효율이 아니라 등급 기준값이다.

---

## 5. 모니터: 초당 픽셀 처리량

```
점수(Mpx/s) = 가로 픽셀 × 세로 픽셀 × 주사율(Hz) ÷ 1,000,000
```

| 예시 | 계산 | 점수 |
| --- | --- | ---: |
| FHD 180Hz | 1920 × 1080 × 180 | 373 |
| QHD 165Hz | 2560 × 1440 × 165 | 608 |
| 4K 240Hz | 3840 × 2160 × 240 | 1,991 |

- 해상도(선명함)와 주사율(부드러움)을 하나의 숫자로 합친 값이다.
- 모니터 화질 벤치마크(색 정확도, 응답속도)는 측정 기관마다 방식이 달라 일관된 수치를 얻기 어렵다.

**한계:** 패널 종류(IPS/VA/OLED)와 색 품질은 반영하지 않는다. **외부 출처가 아닌 자체 공식**이다.

---

## 6. 메인보드: 점수 없음 (NULL)

- 메인보드는 CPU·메모리 성능을 전달하는 부품이라 **단일 성능 벤치마크가 존재하지 않는다.**
- 칩셋 등급(Z > B > H, X > B > A)으로 점수를 만들 수는 있지만 **출처가 없는 자체 기준**이 된다.
- 근거 없는 값을 섞지 않기 위해 NULL로 두었다.

---

## 7. DB 설계에 반영한 방식

```sql
ALTER TABLE modules
    ADD COLUMN performance_score INT NULL AFTER price,
    ADD KEY idx_modules_category_score (category_id, performance_score);
```

- **공통 테이블 `modules`에 컬럼 1개**: 8개 상세 테이블에 따로 두지 않고, 정렬과 검색을 한 곳에서 처리한다.
- **NULL 허용**: 지표가 없는 카테고리(메인보드)를 표현한다.
- **복합 인덱스 `(category_id, performance_score)`**: "카테고리별 성능순" 조회를 인덱스로 처리한다.
  ```sql
  SELECT name, price, performance_score
  FROM modules
  WHERE category_id = ?
  ORDER BY performance_score DESC;
  ```
- **NL2SQL 연동**: LLM이 참고하는 스키마 설명(`schema_docs.json`)에 "같은 카테고리 안에서만 비교"
  규칙과 카테고리별 단위를 적어서, "성능 좋은 GPU" 같은 질문에 올바른 쿼리를 만들게 했다.
