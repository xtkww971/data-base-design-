# 0001: NL2SQL 구현을 위한 프레임워크로 LangGraph를 사용
작성일자:2026-09-27

작성자: 김유현
## 상태
Accepted
## 컨텍스트
자연어를 SQL쿼리로 변환하는 NL2SQL 시스템은 사용자의 모호한 질문을 처리하고 복잡한 데이터베이스 스키마를 매핑하여 보다 정확한 쿼리를 생성해 낼 수 있도록 해야한다. 단일 LLM호출로는 테이블의 정보를 알 수 없고 조인이나 예외처리를 정교하게 해낼 수 없다. 이를 극복하기 위해서 에이전트 아키텍쳐 구현이 필요하다. 특히 NL2SQL의 신뢰성을 높이기 위해 생성-> 검증-> 피드백 및 재생성 구조를 구현해야 할 필요가 있다.
## 결정
복잡한 NL2SQL의 구조와 생성 흐름을 구현하고 관리하기 위해 LangGraph 프레임워크 기반으로 시스템을 개발하기로 결정한다.
## 근거
- 순환 구조 지원: SQL 생성 -> 검증 -> 실패 시 피드백 및 수정 -> 재검증의 피드백-재생성 구조를 LangGraph의 그래프 엣지 정의로 깔끔하게 구현 할 수 있다.
- State 관리: 생성된 쿼리문과 에러 사항 등을 State에 넣고 이를 Node간에 공유하며 신뢰성있는 쿼리문을 생성 할 수 있다.
- RAG 사용의 이점: DB의 스키마 정보를 읽어 올 수 있는 RAG 데이터를 벡터데이터로 저장하고 LLM이 읽어 올 수 있는 노드 구현을 통해 쿼리문의 신뢰성을 높일 수 있다.
- langSmith를 통한 디버깅 용이: LangSmith를 이용하면 LLM이 input이 들어와서 최종 ouput이 나오기까지의 과정에서 어떤 데이터를 어떻게 가공 했는지 알기 쉽기때문에 프로그램 구현에 큰 도움이 된다.
- ## 대안
- LangChain 프레임워크: NL2SQL 검증-> 재시도의 순환구조가 필수적이지만 LangChain은 단순 비순환적 구조를 지원하므로 NL2SQL 구현에 적합하지 않다.
- LLM API 호출을 통한 직접 구현: 모든 코드를 직접 구현해야 하므로 개발비용 측면에서 불리하다.
## 결과
- SQL 생성 오류 발생 시 스스로 피드백을 통해 쿼리를 수정하여 신뢰도가 향상된다.
- 문제 발생 시 LangSmith를 통한 디버깅으로 쿼리 생성-피드백-재생성 과정의 문제점을 쉽게 파악할 수 있어 코드 수정에 유리해진다.
