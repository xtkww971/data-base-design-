# 04. 부품별 제약조건

부품에 걸리는 제약을 성격에 따라 다섯 가지로 나누고, 부품별로 어떤 제약이 걸리는지 정리한다.

| 분류 | 내용 | 예 | 판별 (조회로 위반을 알 수 있나) | 강제 (DB가 저장을 거부하나) |
| --- | --- | --- | --- | --- |
| 값 제약 | 부품 한 개의 숫자 스펙이 말이 되는 값인지 | 코어 수 > 0 | 가능 | `CHECK`, [`V7`](../../backend/src/main/resources/db/migration/V7__add_component_constraints.sql) 작성 |
| **A** 단일 부품 정합성 | 부품 한 개 안의 스펙 조합이 실제로 존재하는지 | AM5 보드는 DDR5만 | 가능 | 조회 테이블 + 복합 FK (V7) |
| **B** 부품 간 하드 규칙 | 함께 고른 부품끼리 조립이 되는지 | DDR4 보드 + DDR5 램 금지 | 가능 (4-3 판별 뷰·쿼리) | `builds` + 복합 FK + `CHECK` (V7) |
| **W** 부품 간 경고 규칙 | 조립은 되지만 성능·기능에서 손해를 보는지 | 램 4개 장착 시 클럭 하락 | 가능 (5-3 쌍 단위 경고 뷰) | 강제하지 않음 (저장은 허용하고 경고만) |
| **C** 보류 | 지금 컬럼이나 테이블로는 표현할 수 없음 | 그래픽카드 길이 ↔ 케이스 | 불가 | 컬럼·테이블 추가 후 B나 W로 이동 |

**판별과 강제를 구분한다.** "이 CPU와 이 보드가 맞는가"는 상세 테이블끼리 조인하면 견적 테이블 없이도
알 수 있다(판별). 장바구니처럼 아직 저장하지 않은 조합도 고른 부품 id만 넘기면 하드 규칙 위반과
경고를 미리 보여줄 수 있다. 견적 테이블(`builds`)이 필요한 것은 두 가지뿐이다.

1. 위반 조합의 저장을 DB가 거부하는 것 (강제)
2. 저장된 견적의 경고를 나중에 다시 조회하는 것 (5-2 `v_build_warnings`)

**적용 상태**: 이 문서의 A·B·W 스키마는 모두
[`V7__add_component_constraints.sql`](../../backend/src/main/resources/db/migration/V7__add_component_constraints.sql)에
들어 있다. 견적 테이블은 [4-4의 선택지 1](#4-4-b를-db에-거는-방법)(`builds`)로 만들었고, 결정 내용은
[8장](#8-결정-사항)에 있다. 문서의 SQL과 V7이 다르면 V7이 기준이다. 시드
[`dummy_modules.sql`](../../backend/src/main/resources/db/seed/dummy_modules.sql)은 카테고리별 150개로 다시 만들었고,
새 컬럼과 `cpu_memory_clocks` 값을 채웠다(9장).

> 버전 안내: V6은 성능 점수 컬럼을 추가하는
> [`V6__add_module_performance_score.sql`](../../backend/src/main/resources/db/migration/V6__add_module_performance_score.sql)이
> 이미 쓰고 있다. Flyway 마이그레이션 버전은 중복될 수 없으므로 값 제약과 A·B·W를 모두 V7 한 파일에 넣었다.
> V7은 아직 커밋 전이라 내용을 바꿨다. 이미 V7을 적용한 로컬 DB가 있으면 9-2를 따라 DB를 다시 만든다.

## 1. 단위와 데이터 해석

규칙을 계산하기 전에 시드 데이터([`dummy_modules.sql`](../../backend/src/main/resources/db/seed/dummy_modules.sql))에서
확인한 컬럼 의미를 먼저 고정한다.

| 컬럼 | 의미 | 근거 |
| --- | --- | --- |
| `rams.capacity` | **키트 전체** 용량(GB) | `32GB(16Gx2)` → `capacity = 32`, `package_count = 2` |
| `rams.package_count` | 키트 안의 모듈(스틱) 수 | 위와 같음 |
| `rams.clock` | 전송 속도 **MT/s** | V4 주석에는 MHz로 적혀 있지만 값(5600 등)은 MT/s다. [03 문서](./03-부품-성능-점수.md)도 MT/s로 계산한다 |
| `graphic_cards.recommended_power` | GPU 단독 소비 전력이 아니라 제조사의 **시스템 전체 권장 파워**(W) | NVIDIA RTX 4060 시스템 파워 550W |

따라서 견적의 램 총 모듈 수는 `package_count × 수량`, 총 용량은 `capacity × 수량`으로 계산한다.
CPU의 메모리 지원 클럭 등 새로 추가하는 클럭 컬럼도 MT/s로 맞춘다.

## 2. 부품별 제약 요약

각 부품에 걸리는 제약을 한곳에 모았다. 규칙 ID는 3~6장의 상세 설명과 같다.

- **판별**: 조회로 위반 여부를 알 수 있는지. 견적 테이블과 관계없다.
- **강제**: DB가 위반 데이터의 저장을 거부하는지. W는 경고라서 강제하지 않는다.

### 2-0. 공통 (`modules`)

| 분류 | 규칙 | 판별 | 강제 |
| --- | --- | --- | --- |
| 값 | `price >= 0` (무료 허용) | 가능 | V7 |
| 값 | `performance_score`는 `NULL` 또는 `>= 0` | 가능 | V7 |
| B6 | 완성 견적에는 CPU, 보드, 램, 파워가 모두 있어야 함 | 고른 부품 목록으로 가능 | V7 `builds` |

### 2-1. CPU (`cpus`)

| 분류 | 규칙 | 판별 | 강제 |
| --- | --- | --- | --- |
| 값 | `cores > 0` | 가능 | V7 |
| 값·A4 | `threads >= cores` | 가능 | V7 |
| A3 | `socket`을 `sockets` 조회 테이블 값으로 제한 | 가능 | 조회 테이블 FK |
| B1 | CPU 소켓 = 보드 소켓 | 가능 (`v_cpu_board_compat`) | V7 `builds` |
| B4·B6 | 내장 그래픽이 없으면(`has_graphics = 0`) 그래픽카드 필수 | 고른 부품 목록으로 가능 | V7 `builds` |
| W1 | 램 클럭 > CPU 공식 지원 클럭 | 가능 (`v_cpu_ram_warnings`) | 강제 안 함 |
| W2 | 램 4개 장착 시 CPU 공식 지원 클럭 하락 | 가능 (`v_cpu_ram_warnings`) | 강제 안 함 |
| W4 | 오버클럭 CPU + CPU 오버클럭 불가 칩셋 | 가능 (`v_cpu_board_warnings`) | 강제 안 함 |
| W5 | 고TDP CPU + 저가 칩셋 보드 | 가능 (`v_cpu_board_warnings`) | 강제 안 함 |
| C | CPU 소비전력을 포함한 파워 용량 계산 | `tdp_watt`는 V7에 있음. 계산 규칙은 미정 | 보류 |

CPU의 메모리 규격 호환은 별도 규칙이 필요 없다. A1(소켓별 허용 메모리 규격), B1(CPU↔보드 소켓),
B2(램↔보드 규격)가 연결되면 "AM5 CPU → AM5 보드 → DDR5 램"이 자동으로 보장된다.

### 2-2. 메인보드 (`main_boards`)

메인보드는 CPU, 램, 저장장치가 모두 꽂히는 호환성 판정의 중심이다.

| 분류 | 규칙 | 판별 | 강제 |
| --- | --- | --- | --- |
| 값 | `memory_slots > 0` | 가능 | V7 |
| A1 | `(socket, memory_spec)`이 허용 조합이어야 함 (AM5→DDR5, AM4→DDR4, LGA1700→DDR4 또는 DDR5) | 가능 | 조회 테이블 복합 FK |
| A2 | `(chipset, socket)`이 일치해야 함 (B650→AM5, B550→AM4, B760→LGA1700 등) | 가능 | 조회 테이블 복합 FK |
| A3 | `socket`, `memory_spec`을 조회 테이블 값으로 제한 | 가능 | 조회 테이블 FK |
| B1 | 보드 소켓 = CPU 소켓 | 가능 (`v_cpu_board_compat`) | V7 `builds` |
| B2 | 보드 메모리 규격 = 램 규격 | 가능 (`v_ram_board_compat`) | V7 `builds` |
| B3 | 램 총 모듈 수 ≤ `memory_slots` | 가능 (`v_ram_board_compat.max_kits`) | V7 `builds` |
| B8 | 램 총 용량 ≤ 보드 최대 메모리 용량 | 가능 (`v_ram_board_compat`) | V7 `builds` |
| B9 | GPU 없이 내장 그래픽만 쓰면 보드에 영상 출력 단자가 있어야 함 | 고른 부품 목록으로 가능 | V7 `builds` |
| W4·W5 | 칩셋의 CPU 오버클럭 지원 여부, 상정 CPU TDP | 가능 (`v_cpu_board_warnings`) | 강제 안 함 |
| C | M.2 슬롯 수, SATA 포트 수, 폼팩터↔케이스, BIOS 업데이트 필요 여부 | 불가 | 보류 |

### 2-3. 램 (`rams`)

| 분류 | 규칙 | 판별 | 강제 |
| --- | --- | --- | --- |
| 값 | `capacity`, `clock`, `package_count` 각각 `> 0` | 가능 | V7 |
| A3 | `memory_spec`을 `memory_specs` 조회 테이블 값으로 제한 | 가능 | 조회 테이블 FK |
| **B2** | **램 규격 = 보드 메모리 규격 (DDR4 보드에 DDR5 램 장착 금지, 반대도 금지)** | **가능** (`v_ram_board_compat`) | V7 `builds` |
| B3 | `package_count × 수량 ≤ 보드 memory_slots` | 가능 (`v_ram_board_compat.max_kits`) | V7 `builds` |
| B8 | `capacity × 수량 ≤ 보드 max_memory_gb` | 가능 (`v_ram_board_compat.max_kits`) | V7 `builds` |
| W1 | 램 클럭 > CPU 공식 지원 클럭 (XMP/EXPO를 켜야 표기 속도) | 가능 (`v_cpu_ram_warnings`) | 강제 안 함 |
| W2 | 모듈 4개 장착 시 공식 지원 클럭 하락 | 가능 (`v_cpu_ram_warnings`) | 강제 안 함 |
| W3 | 모듈 1개만 장착하면 싱글 채널 | 가능 (`package_count`, 수량) | 강제 안 함 |

### 2-4. 그래픽카드 (`graphic_cards`)

| 분류 | 규칙 | 판별 | 강제 |
| --- | --- | --- | --- |
| 값 | `memory_capacity`, `length_mm`, `recommended_power` 각각 `> 0` | 가능 | V7 |
| B5 | 파워 정격 ≥ 그래픽카드 권장 파워 | 가능 (`v_gpu_power_compat`) | V7 `builds` |
| B7 | 그래픽카드 보조전원 커넥터 ↔ 파워 커넥터 | 가능 (`v_gpu_power_compat`) | V7 `builds` |
| C | 카드 길이 ↔ 케이스, 출력 단자 ↔ 모니터 (W6) | 불가 | 보류 |

### 2-5. 파워 (`power`)

| 분류 | 규칙 | 판별 | 강제 |
| --- | --- | --- | --- |
| 값 | `rated_power > 0` | 가능 | V7 |
| B5 | 정격 출력 ≥ 그래픽카드 권장 파워 | 가능 (`v_gpu_power_compat`) | V7 `builds` |
| B7 | PCIe 8핀 개수·16핀(12VHPWR) 지원 ↔ 그래픽카드 | 가능 (`v_gpu_power_compat`) | V7 `builds` |
| C | 폼팩터(ATX/SFX) ↔ 케이스, CPU 포함 소비전력 합산 | 불가 | 보류 |

### 2-6. SSD (`ssds`)

| 분류 | 규칙 | 판별 | 강제 |
| --- | --- | --- | --- |
| 값 | `capacity`, `read_speed`, `write_speed` 각각 `> 0` | 가능 | V7 |
| C | M.2 SSD 개수 ≤ 보드 M.2 슬롯 수, 2.5인치 SSD + HDD 개수 ≤ SATA 포트 수 | 불가 | 보류 |

### 2-7. HDD (`hdds`)

| 분류 | 규칙 | 판별 | 강제 |
| --- | --- | --- | --- |
| 값 | `capacity`, `rpm` 각각 `> 0`, `buffer_memory >= 0` | 가능 | V7 |
| C | 2.5인치 SSD + HDD 개수 ≤ SATA 포트 수 | 불가 | 보류 |

### 2-8. 모니터 (`monitors`)

| 분류 | 규칙 | 판별 | 강제 |
| --- | --- | --- | --- |
| 값 | `screen_size`, `refresh_rate` 각각 `> 0` | 가능 | V7 |
| B4·B9 | 영상 출력원(그래픽카드 또는 내장 그래픽 + 보드 단자)이 있어야 함 | 고른 부품 목록으로 가능 | V7 `builds` |
| W6·C | 모니터 해상도·주사율 ↔ GPU 출력 규격 대역폭 | 불가 (단자 정규화 필요) | 보류 |

## 3. A. 단일 부품 정합성 (V7)

| ID | 테이블 | 규칙 | 근거 | 거는 방법 |
| --- | --- | --- | --- | --- |
| A1 | `main_boards` | 소켓과 메모리 규격의 허용 조합: AM5→DDR5만, AM4→DDR4만, LGA1700→DDR4 또는 DDR5 (보드마다 둘 중 하나) | AM5는 DDR5만 지원, AM4는 DDR4 소켓. LGA1700은 DDR4·DDR5 모두 가능하고 어느 쪽인지는 보드가 결정 | `socket_memory_specs` + 복합 FK `(socket, memory_spec)` |
| A2 | `main_boards` | 칩셋과 소켓 일치: B650·A620·X670→AM5, B550·A520→AM4, B760·Z790·H610→LGA1700 | 소켓별 칩셋 목록 | `chipsets(chipset, socket)` + 복합 FK `(chipset, socket)` |
| A3 | `cpus`, `rams`, `main_boards` | `socket`, `memory_spec` 값을 정해진 목록으로 제한 | — | 조회 테이블 FK. `CHECK (... IN (...))`와 달리 DDR6이 나와도 INSERT 한 줄로 추가된다 |
| A4 | `cpus` | `threads >= cores` | 스레드는 코어 수 이상 | `CHECK` (V7 작성) |

시드 데이터의 보드 6개(LGA1700+DDR5 2개, AM5+DDR5 3개, AM4+DDR4 1개)는 A1과 A2를 모두 통과한다.

```sql
CREATE TABLE sockets
(
    socket VARCHAR(20) NOT NULL,
    PRIMARY KEY (socket)
) DEFAULT CHARSET = utf8mb4;

CREATE TABLE memory_specs
(
    memory_spec VARCHAR(10) NOT NULL,
    PRIMARY KEY (memory_spec)
) DEFAULT CHARSET = utf8mb4;

-- A1: 소켓이 지원하는 메모리 규격. LGA1700 처럼 두 규격을 지원하면 행이 두 개다.
CREATE TABLE socket_memory_specs
(
    socket      VARCHAR(20) NOT NULL,
    memory_spec VARCHAR(10) NOT NULL,
    PRIMARY KEY (socket, memory_spec),
    KEY idx_socket_memory_specs_memory_spec (memory_spec),
    CONSTRAINT fk_socket_memory_specs_socket FOREIGN KEY (socket) REFERENCES sockets (socket),
    CONSTRAINT fk_socket_memory_specs_memory_spec FOREIGN KEY (memory_spec) REFERENCES memory_specs (memory_spec)
) DEFAULT CHARSET = utf8mb4;

-- A2: 칩셋이 속한 소켓. supports_cpu_oc, rated_cpu_tdp_watt 는 경고 규칙 W4, W5 용 (5장)
CREATE TABLE chipsets
(
    chipset            VARCHAR(30) NOT NULL,
    socket             VARCHAR(20) NOT NULL,
    supports_cpu_oc    BIT(1)      NOT NULL,
    rated_cpu_tdp_watt INT         NULL,
    PRIMARY KEY (chipset),
    UNIQUE KEY uk_chipsets_chipset_socket (chipset, socket),
    CONSTRAINT fk_chipsets_socket FOREIGN KEY (socket) REFERENCES sockets (socket),
    CONSTRAINT ck_chipsets_rated_cpu_tdp_positive CHECK (rated_cpu_tdp_watt > 0)
) DEFAULT CHARSET = utf8mb4;

INSERT INTO sockets (socket) VALUES ('LGA1700'), ('AM4'), ('AM5');
INSERT INTO memory_specs (memory_spec) VALUES ('DDR4'), ('DDR5');
INSERT INTO socket_memory_specs (socket, memory_spec)
VALUES ('LGA1700', 'DDR4'),
       ('LGA1700', 'DDR5'),
       ('AM4', 'DDR4'),
       ('AM5', 'DDR5');
-- rated_cpu_tdp_watt: 칩셋이 상정하는 CPU TDP. 제한이 알려지지 않았으면 NULL
-- CPU 오버클럭: 인텔은 Z 시리즈만, AMD 는 A 시리즈와 B840 을 뺀 칩셋
INSERT INTO chipsets (chipset, socket, supports_cpu_oc, rated_cpu_tdp_watt)
VALUES ('Z790', 'LGA1700', 1, NULL),
       ('Z690', 'LGA1700', 1, NULL),
       ('H770', 'LGA1700', 0, NULL),
       ('H670', 'LGA1700', 0, NULL),
       ('B760', 'LGA1700', 0, NULL),
       ('B660', 'LGA1700', 0, NULL),
       ('H610', 'LGA1700', 0, NULL),
       ('X870E', 'AM5', 1, NULL),
       ('X870', 'AM5', 1, NULL),
       ('B850', 'AM5', 1, NULL),
       ('B840', 'AM5', 0, NULL),
       ('X670E', 'AM5', 1, NULL),
       ('X670', 'AM5', 1, NULL),
       ('B650E', 'AM5', 1, NULL),
       ('B650', 'AM5', 1, NULL),
       ('A620', 'AM5', 0, 65),
       ('X570', 'AM4', 1, NULL),
       ('B550', 'AM4', 1, NULL),
       ('B450', 'AM4', 1, NULL),
       ('A520', 'AM4', 0, NULL);

-- A3: 상세 테이블이 조회 테이블을 참조
ALTER TABLE cpus
    ADD CONSTRAINT fk_cpus_socket FOREIGN KEY (socket) REFERENCES sockets (socket);

ALTER TABLE rams
    ADD CONSTRAINT fk_rams_memory_spec FOREIGN KEY (memory_spec) REFERENCES memory_specs (memory_spec);

-- A1, A2: 보드의 스펙 조합이 실제로 존재하는 조합인지
ALTER TABLE main_boards
    ADD CONSTRAINT fk_main_boards_socket_memory_spec
        FOREIGN KEY (socket, memory_spec) REFERENCES socket_memory_specs (socket, memory_spec),
    ADD CONSTRAINT fk_main_boards_chipset_socket
        FOREIGN KEY (chipset, socket) REFERENCES chipsets (chipset, socket);
```

- 조회 테이블의 초기값은 시드 데이터(150개)의 보드가 쓰는 소켓·칩셋이다. 칩셋은 LGA1700 7종, AM5 9종,
  AM4 4종으로 소켓별 칩셋 목록(출처의 Wikipedia 소켓 문서)에 있는 것만 넣었다. 새 소켓·칩셋의 부품을
  등록하려면 조회 테이블 행을 먼저 추가해야 하며, 이것이 의도한 동작이다.
- B840은 AM5 800 시리즈 중 CPU 오버클럭을 지원하지 않는 칩셋이라 `supports_cpu_oc = 0`으로 넣었다.
  A620 외 칩셋의 `rated_cpu_tdp_watt`는 공개된 제한이 없어 NULL이다.
- 복합 FK의 참조 대상은 같은 컬럼 순서의 PK나 UNIQUE 키여야 한다. 그래서 `chipsets`에
  `(chipset, socket)` UNIQUE를 따로 둔다.

**적용 전 확인**: FK는 기존 데이터에도 적용된다. 아래 조회 결과가 위 조회 테이블 값 안에 모두
들어가는지 먼저 확인한다.

```sql
SELECT 'socket' AS code_type, socket AS code_value FROM cpus
UNION
SELECT 'socket', socket FROM main_boards
UNION
SELECT 'memory_spec', memory_spec FROM rams
UNION
SELECT 'socket+memory_spec', CONCAT(socket, '+', memory_spec) FROM main_boards
UNION
SELECT 'chipset+socket', CONCAT(chipset, '+', socket) FROM main_boards;
```

## 4. B. 부품 간 하드 규칙 (판별은 판별 뷰, 강제는 `builds`)

조립 자체가 안 되거나 동작하지 않는 조합이다. 출력할 때는 후보에서 빼고(4-3), 저장할 때는 DB가
거부해야 한다(4-4).

### 4-1. 지금 컬럼으로 가능한 규칙

| ID | 규칙 | 비교 컬럼 | 근거 |
| --- | --- | --- | --- |
| B1 | CPU 소켓 = 보드 소켓 | `cpus.socket = main_boards.socket` | 14세대 인텔은 LGA1700과 600/700 시리즈 칩셋 보드가 필요 |
| **B2** | **램 규격 = 보드 메모리 규격** | `rams.memory_spec = main_boards.memory_spec` | DDR5와 DDR4는 핀 배열과 홈 위치가 달라 서로의 슬롯에 들어가지 않음 |
| B3 | 램 총 모듈 수 ≤ 보드 슬롯 수 | `rams.package_count × 수량 ≤ main_boards.memory_slots` | 물리적 슬롯 수 |
| B4 | 내장 그래픽이 없는 CPU면 그래픽카드 필수 | `cpus.has_graphics = 0` → GPU 있음 | 인텔 F 접미사 CPU는 내장 그래픽이 없어 외장 그래픽카드가 필요함 |
| B5 | 파워 정격 ≥ 그래픽카드 권장 파워 | `power.rated_power ≥ graphic_cards.recommended_power` | NVIDIA는 RTX 4060에 시스템 파워 550W를 요구하며, 이 값은 Ryzen 9 5900X 시스템 기준 |
| B6 | 완성 견적의 필수 구성: `status = 'COMPLETE'`이면 CPU, 보드, 램, 파워가 모두 있어야 하고, GPU가 있거나 CPU에 내장 그래픽이 있어야 함 (B4 포함) | 견적의 `status`와 각 부품 칸 | 작성 중(`DRAFT`)인 견적은 빈 칸을 허용 |

- 시드에는 600W 파워 + RTX 4080 SUPER(권장 750W) 같은 B5 위반 조합이 있어 테스트 데이터로 쓰기 좋다.
- B5는 CPU 소비전력을 포함하지 않은 최소 검사다. `cpus.tdp_watt`는 V7에서 추가했지만, CPU와 GPU 전력을
  합산하는 규칙(안전계수 등)은 아직 정하지 않았다(6장 C).
- 저장장치를 별도 테이블(`build_storages`)에 두면 "저장장치 최소 1개" 조건은 `CHECK`로 표현할
  수 없다. 트리거로 검사하거나 애플리케이션에서 처리한다.

### 4-2. 컬럼을 추가해 가능해진 규칙 (V7에서 추가)

| ID | 규칙 | 추가할 컬럼 | 근거 |
| --- | --- | --- | --- |
| B7 | 그래픽카드 보조전원 ↔ 파워 커넥터 | `graphic_cards.uses_16pin`, `graphic_cards.pcie_8pin_count`, `power.has_16pin`, `power.pcie_8pin_count` | RTX 40 레퍼런스 카드는 12VHPWR(16핀)을 쓰고, 동봉 어댑터가 PCIe 8핀 여러 개를 16핀으로 변환한다. 서드파티 카드 중에는 일반 8핀을 쓰는 제품도 있다 |
| B8 | 램 총 용량 ≤ 보드 최대 메모리 용량 | `main_boards.max_memory_gb` | 보드 사양 |
| B9 | GPU 없이 내장 그래픽만 쓰면 보드에 영상 출력 단자가 있어야 함 | `main_boards.has_video_output` | 내장 그래픽은 보드 단자를 통해 출력됨 |

- B7의 `graphic_cards.pcie_8pin_count`는 카드가 요구하는 PCIe 8핀 개수다. 16핀 카드는 동봉
  어댑터가 요구하는 8핀 개수를 넣는다. 파워에 16핀 케이블이 있으면 어댑터 없이 바로 연결된다.
- 추가 컬럼은 시드 데이터의 실제 제품 사양을 확인해 함께 채워야 한다. 값을 모르는 상태로 0이나
  임의 값을 넣지 않는다.

```sql
ALTER TABLE graphic_cards
    ADD COLUMN uses_16pin      BIT(1) NOT NULL DEFAULT 0,
    ADD COLUMN pcie_8pin_count INT    NOT NULL DEFAULT 0,
    ADD CONSTRAINT ck_graphic_cards_pcie_8pin_count_nonnegative CHECK (pcie_8pin_count >= 0);

ALTER TABLE power
    ADD COLUMN has_16pin       BIT(1) NOT NULL DEFAULT 0,
    ADD COLUMN pcie_8pin_count INT    NOT NULL DEFAULT 0,
    ADD CONSTRAINT ck_power_pcie_8pin_count_nonnegative CHECK (pcie_8pin_count >= 0);

ALTER TABLE main_boards
    ADD COLUMN max_memory_gb    INT    NULL,
    ADD COLUMN has_video_output BIT(1) NULL,
    ADD CONSTRAINT ck_main_boards_max_memory_gb_positive CHECK (max_memory_gb > 0);
```

- `DEFAULT 0`은 ALTER 시점에 기존 행을 채우기 위한 것이다. V7은 기존 행의 값을 UPDATE하지 않는다.
  새 시드는 모든 부품에 커넥터 값을 넣으므로, 9-2처럼 DB를 다시 만들고 시드를 넣으면 0이 남지 않는다.
- `main_boards.max_memory_gb`, `has_video_output`은 NULL을 허용한다. 값을 모르는 보드는 B8·B9를 판정하지 않는다.
- 부품 등록 API(JPA 엔티티)는 아직 이 컬럼들을 받지 않는다. API로 등록한 그래픽카드·파워는 커넥터 값이 0,
  보드는 NULL로 저장된다(9-3).

### 4-3. 견적 테이블 없이 판별하기

B1·B2·B3·B5는 부품 두 개의 스펙만 비교하므로, 상세 테이블끼리 조인하면 견적 테이블 없이 지금 판별할 수
있다. 판별 결과는 두 가지 방식으로 쓴다.

- **후보 고르기**: 이미 고른 부품과 호환되는 후보만 출력한다 (아래 쌍 단위 판별 뷰).
- **장바구니 미리 검사**: 저장하기 전에 고른 부품 id를 넘겨 위반 규칙을 받는다 (아래 판별 쿼리).

#### 쌍 단위 판별 뷰

호환되는 쌍만 돌려준다. 뷰에 없는 쌍은 하드 규칙 위반이다.

```sql
-- B1: 소켓이 같은 CPU × 보드
CREATE VIEW v_cpu_board_compat AS
SELECT c.module_id AS cpu_id, mb.module_id AS board_id
FROM cpus c
         JOIN main_boards mb ON mb.socket = c.socket;

-- B2, B3, B8: 규격이 같고 키트 하나가 슬롯·최대 용량 안에 들어가는 램 × 보드
-- max_kits: 이 키트를 최대 몇 세트까지 담을 수 있는지 (B3, B8 의 수량 상한)
CREATE VIEW v_ram_board_compat AS
SELECT r.module_id AS ram_id,
       mb.module_id AS board_id,
       LEAST(mb.memory_slots DIV r.package_count,
             COALESCE(mb.max_memory_gb DIV r.capacity, mb.memory_slots DIV r.package_count)) AS max_kits
FROM rams r
         JOIN main_boards mb ON mb.memory_spec = r.memory_spec
WHERE r.package_count <= mb.memory_slots
  AND (mb.max_memory_gb IS NULL OR r.capacity <= mb.max_memory_gb);

-- CPU 의 소켓이 지원하는 규격의 램 (보드를 아직 고르지 않았을 때). A1 + B1 + B2 를 합친 결과
CREATE VIEW v_cpu_ram_compat AS
SELECT c.module_id AS cpu_id, r.module_id AS ram_id
FROM cpus c
         JOIN socket_memory_specs sms ON sms.socket = c.socket
         JOIN rams r ON r.memory_spec = sms.memory_spec;

-- B5, B7: 정격 출력과 보조전원 커넥터가 맞는 그래픽카드 × 파워
CREATE VIEW v_gpu_power_compat AS
SELECT g.module_id AS gpu_id, p.module_id AS power_id
FROM graphic_cards g
         JOIN power p ON p.rated_power >= g.recommended_power
WHERE p.pcie_8pin_count >= g.pcie_8pin_count
   OR (g.uses_16pin = 1 AND p.has_16pin = 1);
```

- `v_cpu_ram_compat`는 LGA1700 CPU에 DDR4와 DDR5 램을 모두 돌려준다. 보드에 따라 둘 중 하나로 정해지므로,
  보드를 고른 뒤에는 `v_ram_board_compat`로 다시 좁힌다.
- `v_cpu_ram_compat`는 `socket_memory_specs`(A1)를 참조한다.
- B7은 `v_gpu_power_compat`, B8은 `v_ram_board_compat`에 함께 들어 있다. B9는 부품 쌍이 아니라 견적 전체
  구성(그래픽카드 유무)에 대한 규칙이라 아래 미리 검사 쿼리나 `builds`의 `CHECK`로 판별한다.

예: "라이젠5 7500F와 호환되는 메인보드"

```sql
SELECT m.*
FROM v_cpu_board_compat v
         JOIN modules m ON m.module_id = v.board_id
WHERE v.cpu_id = ?;
```

#### 장바구니 미리 검사 쿼리

고른 부품 id를 파라미터로 넘기면 위반한 규칙을 행으로 돌려준다. 결과가 비어 있으면 하드 규칙을 모두
통과한 조합이다. 아직 고르지 않은 칸은 NULL로 넘긴다. `module_id = NULL`은 참이 되지 않으므로 그 칸이
들어간 규칙은 판정하지 않는다.

```sql
-- 파라미터: :cpu_id, :board_id, :ram_id, :ram_qty, :gpu_id, :power_id, :complete (확정 요청이면 1)
SELECT 'B1' AS rule_id
FROM cpus c
         JOIN main_boards mb ON mb.module_id = :board_id
WHERE c.module_id = :cpu_id
  AND c.socket <> mb.socket
UNION ALL
SELECT 'B2'
FROM rams r
         JOIN main_boards mb ON mb.module_id = :board_id
WHERE r.module_id = :ram_id
  AND r.memory_spec <> mb.memory_spec
UNION ALL
SELECT 'B3'
FROM rams r
         JOIN main_boards mb ON mb.module_id = :board_id
WHERE r.module_id = :ram_id
  AND r.package_count * :ram_qty > mb.memory_slots
UNION ALL
SELECT 'B5'
FROM graphic_cards g
         JOIN power p ON p.module_id = :power_id
WHERE g.module_id = :gpu_id
  AND p.rated_power < g.recommended_power
UNION ALL
-- B4: 내장 그래픽 없는 CPU 인데 그래픽카드를 고르지 않음 (확정할 때만 판정)
SELECT 'B4'
FROM cpus c
WHERE c.module_id = :cpu_id
  AND c.has_graphics = 0
  AND :gpu_id IS NULL
  AND :complete = 1
UNION ALL
-- B6: 확정할 때 필수 부품이 빠짐
SELECT 'B6'
FROM DUAL
WHERE :complete = 1
  AND (:cpu_id IS NULL OR :board_id IS NULL OR :ram_id IS NULL OR :power_id IS NULL);
```

- `:name` 표기는 Spring의 `NamedParameterJdbcTemplate`이나 JPA 네이티브 쿼리의 이름 있는 파라미터를 뜻한다.
- 작성 중에 그래픽카드를 아직 고르지 않은 것은 정상 상태이므로, B4·B6은 사용자가 견적을 확정할 때만
  판정한다(`:complete = 1`).
- 같은 파라미터로 5-3의 쌍 단위 경고 뷰를 조회하면 경고도 미리 보여줄 수 있다.
- 이 쿼리는 **판별**일 뿐이다. 서비스나 프론트를 거치지 않고 저장되는 데이터까지 막으려면 4-4의 **강제**가
  필요하다. 두 방식이 같은 규칙을 다르게 구현하지 않도록, 규칙을 바꿀 때는 4-3과 4-4를 함께 고친다.

### 4-4. B를 DB에 거는 방법

#### 선택지 1 (추천): 카테고리별 칸이 있는 `builds` 테이블 + 복합 FK + `CHECK`

트리거 없이 선언적 제약만으로 B1~B9를 걸 수 있다. 상세 테이블에 `(module_id, 스펙…)` UNIQUE를
추가하고, 견적 행이 복합 FK로 스펙 값을 함께 들고 와서 같은 행 안에서 `CHECK`로 비교한다.
MySQL `CHECK`는 다른 테이블을 조회할 수 없지만, 비교할 스펙이 같은 행에 있으면 걸 수 있다.
FK는 복사해 온 스펙 값이 원본 부품의 실제 값과 같다는 것을 보장한다.

```sql
-- 복합 FK 의 참조 대상. module_id 가 이미 PK 라 UNIQUE 는 항상 만족한다.
ALTER TABLE cpus
    ADD UNIQUE KEY uk_cpus_compat (module_id, socket, has_graphics);
ALTER TABLE main_boards
    ADD UNIQUE KEY uk_main_boards_compat (module_id, socket, memory_spec, memory_slots),
    -- NULL 이 될 수 있는 컬럼은 따로 묶는다. 한 FK 에 섞으면 NULL 일 때 소켓·규격 검사까지 건너뛴다.
    ADD UNIQUE KEY uk_main_boards_limits (module_id, max_memory_gb, has_video_output);
ALTER TABLE rams
    ADD UNIQUE KEY uk_rams_compat (module_id, memory_spec, package_count, capacity);
ALTER TABLE graphic_cards
    ADD UNIQUE KEY uk_graphic_cards_compat (module_id, recommended_power, uses_16pin, pcie_8pin_count);
ALTER TABLE power
    ADD UNIQUE KEY uk_power_compat (module_id, rated_power, has_16pin, pcie_8pin_count);

CREATE TABLE builds
(
    build_id               BIGINT       NOT NULL AUTO_INCREMENT,
    user_id                BIGINT       NOT NULL,
    title                  VARCHAR(100) NOT NULL,
    status                 VARCHAR(10)  NOT NULL DEFAULT 'DRAFT',
    cpu_id                 BIGINT       NULL,
    cpu_socket             VARCHAR(20)  NULL,
    cpu_has_graphics       BIT(1)       NULL,
    board_id               BIGINT       NULL,
    board_socket           VARCHAR(20)  NULL,
    board_memory_spec      VARCHAR(10)  NULL,
    board_memory_slots     INT          NULL,
    board_max_memory_gb    INT          NULL,
    board_has_video_output BIT(1)       NULL,
    ram_id                 BIGINT       NULL,
    ram_memory_spec        VARCHAR(10)  NULL,
    ram_package_count      INT          NULL,
    ram_capacity           INT          NULL,
    ram_quantity           INT          NULL,
    gpu_id                 BIGINT       NULL,
    gpu_recommended_power  INT          NULL,
    gpu_uses_16pin         BIT(1)       NULL,
    gpu_pcie_8pin_count    INT          NULL,
    power_id               BIGINT       NULL,
    power_rated_power      INT          NULL,
    power_has_16pin        BIT(1)       NULL,
    power_pcie_8pin_count  INT          NULL,
    created_at             DATETIME(6)  NOT NULL,
    PRIMARY KEY (build_id),
    KEY idx_builds_user_created (user_id, created_at),
    CONSTRAINT fk_builds_user FOREIGN KEY (user_id) REFERENCES users (user_id) ON DELETE CASCADE,
    CONSTRAINT fk_builds_cpu FOREIGN KEY (cpu_id, cpu_socket, cpu_has_graphics)
        REFERENCES cpus (module_id, socket, has_graphics),
    CONSTRAINT fk_builds_board FOREIGN KEY (board_id, board_socket, board_memory_spec, board_memory_slots)
        REFERENCES main_boards (module_id, socket, memory_spec, memory_slots),
    CONSTRAINT fk_builds_board_limits FOREIGN KEY (board_id, board_max_memory_gb, board_has_video_output)
        REFERENCES main_boards (module_id, max_memory_gb, has_video_output),
    CONSTRAINT fk_builds_ram FOREIGN KEY (ram_id, ram_memory_spec, ram_package_count, ram_capacity)
        REFERENCES rams (module_id, memory_spec, package_count, capacity),
    CONSTRAINT fk_builds_gpu FOREIGN KEY (gpu_id, gpu_recommended_power, gpu_uses_16pin, gpu_pcie_8pin_count)
        REFERENCES graphic_cards (module_id, recommended_power, uses_16pin, pcie_8pin_count),
    CONSTRAINT fk_builds_power FOREIGN KEY (power_id, power_rated_power, power_has_16pin, power_pcie_8pin_count)
        REFERENCES power (module_id, rated_power, has_16pin, pcie_8pin_count),

    CONSTRAINT ck_builds_status CHECK (status IN ('DRAFT', 'COMPLETE')),
    CONSTRAINT ck_builds_ram_quantity_positive CHECK (ram_quantity > 0),

    -- 짝 맞춤: id 와 복사한 스펙은 함께 채우거나 함께 비운다 (주의할 점 1)
    CONSTRAINT ck_builds_cpu_pair CHECK (
        (cpu_id IS NULL) = (cpu_socket IS NULL)
            AND (cpu_id IS NULL) = (cpu_has_graphics IS NULL)),
    CONSTRAINT ck_builds_board_pair CHECK (
        (board_id IS NULL) = (board_socket IS NULL)
            AND (board_id IS NULL) = (board_memory_spec IS NULL)
            AND (board_id IS NULL) = (board_memory_slots IS NULL)),
    -- max_memory_gb, has_video_output 은 원본도 NULL 일 수 있어 보드가 없을 때 비어 있는지만 본다.
    CONSTRAINT ck_builds_board_limits_pair CHECK (
        board_id IS NOT NULL OR (board_max_memory_gb IS NULL AND board_has_video_output IS NULL)),
    CONSTRAINT ck_builds_ram_pair CHECK (
        (ram_id IS NULL) = (ram_memory_spec IS NULL)
            AND (ram_id IS NULL) = (ram_package_count IS NULL)
            AND (ram_id IS NULL) = (ram_capacity IS NULL)
            AND (ram_id IS NULL) = (ram_quantity IS NULL)),
    CONSTRAINT ck_builds_gpu_pair CHECK (
        (gpu_id IS NULL) = (gpu_recommended_power IS NULL)
            AND (gpu_id IS NULL) = (gpu_uses_16pin IS NULL)
            AND (gpu_id IS NULL) = (gpu_pcie_8pin_count IS NULL)),
    CONSTRAINT ck_builds_power_pair CHECK (
        (power_id IS NULL) = (power_rated_power IS NULL)
            AND (power_id IS NULL) = (power_has_16pin IS NULL)
            AND (power_id IS NULL) = (power_pcie_8pin_count IS NULL)),

    -- B1: CPU 소켓 = 보드 소켓
    CONSTRAINT ck_builds_b1_socket CHECK (
        cpu_id IS NULL OR board_id IS NULL OR cpu_socket = board_socket),
    -- B2: 램 규격 = 보드 메모리 규격 (DDR4 보드 + DDR5 램 금지)
    CONSTRAINT ck_builds_b2_memory_spec CHECK (
        ram_id IS NULL OR board_id IS NULL OR ram_memory_spec = board_memory_spec),
    -- B3: 램 총 모듈 수 <= 보드 슬롯 수
    CONSTRAINT ck_builds_b3_memory_slots CHECK (
        ram_id IS NULL OR board_id IS NULL OR ram_package_count * ram_quantity <= board_memory_slots),
    -- B5: 파워 정격 >= 그래픽카드 권장 파워
    CONSTRAINT ck_builds_b5_power CHECK (
        gpu_id IS NULL OR power_id IS NULL OR power_rated_power >= gpu_recommended_power),
    -- B6 (B4 포함): 완성 견적의 필수 구성
    CONSTRAINT ck_builds_b6_complete CHECK (
        status <> 'COMPLETE'
            OR (cpu_id IS NOT NULL AND board_id IS NOT NULL AND ram_id IS NOT NULL AND power_id IS NOT NULL
            AND (gpu_id IS NOT NULL OR cpu_has_graphics = 1))),
    -- B7: 파워 8핀 개수가 충분하거나, 16핀 카드를 16핀 파워에 바로 연결
    CONSTRAINT ck_builds_b7_power_connector CHECK (
        gpu_id IS NULL OR power_id IS NULL
            OR power_pcie_8pin_count >= gpu_pcie_8pin_count
            OR (gpu_uses_16pin = 1 AND power_has_16pin = 1)),
    -- B8: 램 총 용량 <= 보드 최대 메모리 용량 (보드 값을 모르면 판정 안 함)
    CONSTRAINT ck_builds_b8_memory_capacity CHECK (
        ram_id IS NULL OR board_id IS NULL OR board_max_memory_gb IS NULL
            OR ram_capacity * ram_quantity <= board_max_memory_gb),
    -- B9: 그래픽카드 없이 완성하면 보드에 영상 출력 단자가 있어야 한다 (보드 값을 모르면 판정 안 함)
    CONSTRAINT ck_builds_b9_video_output CHECK (
        status <> 'COMPLETE' OR gpu_id IS NOT NULL OR board_has_video_output = 1)
) DEFAULT CHARSET = utf8mb4;

-- 저장장치처럼 여러 개를 담는 부품
CREATE TABLE build_storages
(
    build_id  BIGINT NOT NULL,
    module_id BIGINT NOT NULL,
    quantity  INT    NOT NULL DEFAULT 1,
    PRIMARY KEY (build_id, module_id),
    KEY idx_build_storages_module_id (module_id),
    CONSTRAINT fk_build_storages_build FOREIGN KEY (build_id) REFERENCES builds (build_id) ON DELETE CASCADE,
    CONSTRAINT fk_build_storages_module FOREIGN KEY (module_id) REFERENCES modules (module_id),
    CONSTRAINT ck_build_storages_quantity_positive CHECK (quantity > 0)
) DEFAULT CHARSET = utf8mb4;
```

B7~B9용 복사 컬럼(`gpu_uses_16pin`, `ram_capacity`, `board_max_memory_gb` 등)도 같은 방식으로 들어 있다.
복사 컬럼을 추가할 때는 해당 상세 테이블의 `uk_*` UNIQUE와 `fk_builds_*` FK의 컬럼 목록도 함께 늘린다.

보드의 `max_memory_gb`, `has_video_output`은 NULL일 수 있어서 `fk_builds_board_limits`로 따로 묶었다. 한 FK에
섞으면 그 값이 NULL인 보드를 담을 때 소켓·메모리 규격 검사(`fk_builds_board`)까지 건너뛰게 된다.
대신 `builds`에서 이 두 칸만 NULL로 비우면 B8·B9 판정을 피할 수 있다. 원본도 NULL일 수 있어 짝 맞춤
`CHECK`로 막을 수 없는 한계다. 견적을 저장하는 서비스가 원본 값을 그대로 복사해야 한다.

- **장점**: 위반이 INSERT/UPDATE 시점에 바로 막힌다. 제약 이름(`ck_builds_b2_memory_spec` 등)이
  그대로 에러에 나오므로 프론트 메시지로 매핑하기 쉽다.
- **주의할 점 1**: 복합 FK는 컬럼 중 하나라도 NULL이면 부모 조회를 건너뛰는 것으로 알려져 있다.
  그래서 `cpu_id`만 채우고 `cpu_socket`을 NULL로 두면 검사를 우회할 수 있다. 위의 `ck_builds_*_pair`
  짝 맞춤 `CHECK`가 이를 막는다. MySQL 공식 FK 문서에 이 동작이 명시되어 있지 않아 MySQL 8.4에서 직접
  확인했다. 부모에 없는 `(999, NULL)` 행이 자식 테이블에 들어갔다(9-1).
- **주의할 점 2**: MySQL은 `CHECK`에 쓰인 컬럼에 FK 참조 동작(`ON UPDATE CASCADE` 등)을 금지한다.
  그래서 `fk_builds_*`는 기본값(RESTRICT)으로 둔다. 그 결과 견적에 들어간 부품의 스펙(소켓, 슬롯 수 등)은
  수정과 삭제가 막힌다. 스펙을 고쳐야 하면 해당 견적에서 부품을 먼저 뺀다.
- **한계**: 램은 한 종류 × 수량만 표현된다. 서로 다른 램 키트 두 개는 담을 수 없다. 저장장치처럼
  여러 개를 담는 부품은 `build_storages` 같은 별도 테이블이 필요하고, 그 테이블과의 규칙은
  `CHECK`로 걸 수 없다.

#### 선택지 2: 01 문서 계획대로 `quotes` + `quote_items` + 트리거

```
quotes      (quote_id PK, user_id FK, title, created_at)
quote_items (quote_id FK, module_id FK, quantity, price_snapshot)  PK (quote_id, module_id)
```

부품 개수에 제한이 없어 유연하다. 다만 행이 하나씩 들어가므로 "보드보다 램을 먼저 담은 경우"처럼
비교 대상이 아직 없는 상황이 생긴다. 트리거는 이미 담긴 부품끼리만 검사할 수 있다. 또 MySQL
트리거는 행 단위(`FOR EACH ROW`)만 지원해서 B3처럼 합산이 필요한 규칙을 다루기 어렵고, 위반
메시지도 `SIGNAL`로 직접 만들어야 한다.

#### 비교

| 항목 | 선택지 1 (`builds`) | 선택지 2 (`quote_items` + 트리거) |
| --- | --- | --- |
| 강제 방식 | 선언적 (FK + `CHECK`) | 절차적 (트리거) |
| 위반 시점 | INSERT/UPDATE 즉시 | 트리거가 실행될 때, 이미 담긴 부품끼리만 |
| 부품 개수 | 카테고리당 한 칸 (램은 한 종류 × 수량) | 제한 없음 |
| 에러 메시지 | 제약 이름 그대로 | `SIGNAL`로 직접 작성 |
| 부품 스펙 수정 | 견적에 담긴 부품은 막힘 | 자유 (대신 기존 견적이 위반 상태가 될 수 있음) |

DB 설계 과제라는 점에서, 트리거 없이 선언적으로 보장되는 **선택지 1을 추천**한다.

## 5. W. 경고 규칙 (막지 않고 알려줌)

조립은 되지만 성능이나 기능에서 손해를 보는 조합이다. `CHECK`로 걸면 정상적인 견적까지 거부되므로
**경고 뷰**로 만든다. 견적 하나당 해당되는 경고를 행으로 돌려주는 뷰라서 저장은 막지 않으면서 규칙
자체는 DB에 선언적으로 남는다. 프론트는 이 뷰를 조회해 노란 경고로 보여준다.

| ID | 상황 | 시드 데이터 예시 | 근거 |
| --- | --- | --- | --- |
| W1 | 램 클럭 > CPU 공식 지원 클럭. XMP/EXPO를 켜야 표기 속도가 나오고, 켜지 않으면 낮은 속도로 동작 | DDR5-6000 키트 + 7500F·7800X3D(공식 DDR5-5200), 14600K(공식 DDR5-5600) | AMD 7500F·7800X3D 사양, Intel 14세대 사양 |
| W2 | 램 4개 장착 시 공식 지원 클럭 하락 | 16Gx2 키트 2세트를 AM5 보드에 장착 → 공식 지원 속도가 DDR5-3600으로 내려감 | AMD 사양 (2 DIMM 5200, 4 DIMM 3600) |
| W3 | 싱글 채널: 모듈 1개만 장착하면 대역폭이 절반 | 삼성 DDR5-5600 16GB 1개 | AM5는 2채널. [03 문서](./03-부품-성능-점수.md) RAM 공식의 `min(package_count, 2)`와 같은 논리 |
| W4 | 오버클럭 CPU + CPU 오버클럭 불가 칩셋 | 14600K·14700K(K) + B760 보드 | CPU 오버클럭은 K + Z790 조합에서만 가능하고 B760은 불가. A620도 CPU 오버클럭을 지원하지 않고 메모리 오버클럭만 가능 |
| W5 | A620 보드 + 고TDP CPU: 전원부 한계로 멀티코어 성능이 떨어질 수 있음 | A620 Mini-ITX + 7800X3D (TDP 120W) | AMD는 A620에 65W CPU 사용을 상정 |
| W6 | 모니터 해상도·주사율 ↔ GPU 출력 규격 대역폭 | 4K 240Hz 모니터 | `ports`가 자유 문자열이라 현재는 비교 불가. 단자 테이블로 정규화가 필요해서 **이번 범위에서 제외** |

### 5-1. 필요한 추가 데이터

| 테이블 | 컬럼 | 쓰는 규칙 |
| --- | --- | --- |
| `cpus` | `tdp_watt` | W5 (이후 C의 파워 용량 계산에도 사용) |
| `cpus` | `overclockable` | W4 |
| `cpu_memory_clocks` (신규) | `cpu_id`, `memory_spec`, `max_clock_2dimm`, `max_clock_4dimm` | W1, W2 |
| `chipsets` (A2) | `supports_cpu_oc`, `rated_cpu_tdp_watt` | W4, W5 |

- CPU 공식 지원 클럭은 `cpus.max_memory_clock` 컬럼 하나로 두지 않고 `cpu_memory_clocks` 테이블로
  분리했다. Intel 14세대는 DDR5 최대 5600, DDR4 최대 3200처럼 **메모리 규격마다 지원 클럭이 다르고**,
  AMD는 2 DIMM/4 DIMM일 때 지원 클럭이 다르기 때문이다(W2). 컬럼 하나로는 두 경우를 모두 표현할 수 없다.
- `chipsets`에 `supports_cpu_oc`, `rated_cpu_tdp_watt`를 두면 A2(칩셋↔소켓 정합성)와 W4, W5를 같은
  테이블로 처리할 수 있다.

```sql
ALTER TABLE cpus
    ADD COLUMN tdp_watt      INT    NULL,
    ADD COLUMN overclockable BIT(1) NULL,
    ADD CONSTRAINT ck_cpus_tdp_watt_positive CHECK (tdp_watt > 0);

-- clock 단위: MT/s. 4 DIMM 클럭을 모르면 NULL (W2 판정 안 함)
CREATE TABLE cpu_memory_clocks
(
    cpu_id          BIGINT      NOT NULL,
    memory_spec     VARCHAR(10) NOT NULL,
    max_clock_2dimm INT         NOT NULL,
    max_clock_4dimm INT         NULL,
    PRIMARY KEY (cpu_id, memory_spec),
    CONSTRAINT fk_cpu_memory_clocks_cpu FOREIGN KEY (cpu_id) REFERENCES cpus (module_id) ON DELETE CASCADE,
    CONSTRAINT fk_cpu_memory_clocks_memory_spec FOREIGN KEY (memory_spec) REFERENCES memory_specs (memory_spec),
    CONSTRAINT ck_cpu_memory_clocks_2dimm_positive CHECK (max_clock_2dimm > 0),
    CONSTRAINT ck_cpu_memory_clocks_4dimm_lte_2dimm CHECK (max_clock_4dimm <= max_clock_2dimm)
) DEFAULT CHARSET = utf8mb4;
```

### 5-2. 경고 뷰 (선택지 1의 `builds` 기준)

```sql
CREATE VIEW v_build_warnings AS
-- W1: 램 클럭 > CPU 공식 지원 클럭 (모듈 2개 이하)
SELECT b.build_id, 'W1' AS warning_code
FROM builds b
         JOIN rams r ON r.module_id = b.ram_id
         JOIN cpu_memory_clocks cm ON cm.cpu_id = b.cpu_id AND cm.memory_spec = b.ram_memory_spec
WHERE b.ram_package_count * b.ram_quantity <= 2
  AND r.clock > cm.max_clock_2dimm
UNION ALL
-- W2: 모듈 3개 이상이면 4 DIMM 지원 클럭 기준
SELECT b.build_id, 'W2'
FROM builds b
         JOIN rams r ON r.module_id = b.ram_id
         JOIN cpu_memory_clocks cm ON cm.cpu_id = b.cpu_id AND cm.memory_spec = b.ram_memory_spec
WHERE b.ram_package_count * b.ram_quantity > 2
  AND r.clock > cm.max_clock_4dimm
UNION ALL
-- W3: 싱글 채널
SELECT b.build_id, 'W3'
FROM builds b
WHERE b.ram_package_count * b.ram_quantity = 1
UNION ALL
-- W4: 오버클럭 CPU + CPU 오버클럭 불가 칩셋
SELECT b.build_id, 'W4'
FROM builds b
         JOIN cpus c ON c.module_id = b.cpu_id
         JOIN main_boards mb ON mb.module_id = b.board_id
         JOIN chipsets ch ON ch.chipset = mb.chipset
WHERE c.overclockable = 1
  AND ch.supports_cpu_oc = 0
UNION ALL
-- W5: CPU TDP > 칩셋이 상정하는 CPU TDP
SELECT b.build_id, 'W5'
FROM builds b
         JOIN cpus c ON c.module_id = b.cpu_id
         JOIN main_boards mb ON mb.module_id = b.board_id
         JOIN chipsets ch ON ch.chipset = mb.chipset
WHERE ch.rated_cpu_tdp_watt IS NOT NULL
  AND c.tdp_watt > ch.rated_cpu_tdp_watt;
```

비교 대상 값이 NULL이면(아직 사양을 채우지 않은 CPU·칩셋) 비교 결과가 `UNKNOWN`이 되어 경고가
나오지 않는다. 경고는 데이터가 확인된 부품에만 나온다.

### 5-3. 경고 회피 정렬

5-2의 `v_build_warnings`는 견적을 **저장한 뒤에** 남은 경고를 알려준다. 경고를 피하려면 부품을
**고르는 단계에서** "이미 고른 부품과 이 후보를 함께 쓰면 경고가 나는가"를 알아야 한다. 그래서 출력은
다음 원칙을 따른다.

| 구분 | 출력할 때 처리 |
| --- | --- |
| B (하드 규칙) | 후보에서 뺀다 (4-3의 판별 뷰로 `JOIN`). 출력하지 않는다 |
| W (경고 규칙) | 빼지 않고 뒤로 보낸다 (`ORDER BY 벌점 합계, 성능/가격`) |
| 피할 수 없는 경고 | 숨기지 않는다. 경고 문구와 해결 방법(`how_to_avoid`)을 함께 보여준다 |

경고가 있는 후보를 아예 빼면 예산 안에 대안이 없을 때 결과가 비어 버린다. 따라서 "빼기"가 아니라
"뒤로 보내기"로 처리한다.

#### 경고별 벌점

경고를 무조건 피하는 것이 항상 이득은 아니다. 피하는 데 드는 비용에 따라 벌점을 다르게 준다.

| 경고 | 피하는 방법과 비용 | 벌점 |
| --- | --- | --- |
| W3 싱글 채널 | 같은 용량의 2개짜리 키트를 고르면 된다. 비용이 거의 없다 | 30 |
| W2 램 4개 장착 | 용량이 큰 2개짜리 키트 하나로 바꾸면 된다 | 20 |
| W4 오버클럭 CPU + CPU 오버클럭 불가 칩셋 | 오버클럭 불가 CPU나 오버클럭 지원 칩셋을 고르면 된다 | 20 |
| W5 고TDP CPU + 저가 칩셋 | 상위 칩셋 보드(A620 대신 B650)를 고르면 된다 | 20 |
| W1 램 클럭 > CPU 공식 지원 클럭 | **피하려면 더 느린 램을 골라야 한다** | 0 (안내만) |

W1을 피하는 쪽으로 정렬하면 DDR5-6000 대신 DDR5-5200을 추천하게 된다. 하지만 BIOS에서 XMP/EXPO를 한 번
켜면 6000이 더 빠르다. 그래서 W1은 순위에 반영하지 않고 "XMP/EXPO를 켜세요"라는 안내만 붙인다. 벌점을
테이블에 두면 이런 판단을 SQL 수정 없이 데이터로 바꿀 수 있다.

```sql
-- 경고 규칙별 벌점과 안내 문구. penalty 가 0 이면 정렬에 영향 없이 안내만 한다.
CREATE TABLE warning_rules
(
    warning_code VARCHAR(5)   NOT NULL,
    penalty      INT          NOT NULL,
    message      VARCHAR(200) NOT NULL,
    how_to_avoid VARCHAR(200) NOT NULL,
    PRIMARY KEY (warning_code),
    CONSTRAINT ck_warning_rules_penalty_nonnegative CHECK (penalty >= 0)
) DEFAULT CHARSET = utf8mb4;

INSERT INTO warning_rules (warning_code, penalty, message, how_to_avoid)
VALUES ('W1', 0, '램 클럭이 CPU 공식 지원 클럭보다 높습니다.',
        'BIOS 에서 XMP/EXPO 를 켜야 표기 속도로 동작합니다.'),
       ('W2', 20, '램 4개 장착 시 CPU 공식 지원 클럭이 낮아집니다.',
        '같은 총 용량의 2개짜리 키트 하나를 고르세요.'),
       ('W3', 30, '램 모듈이 1개라 싱글 채널로 동작합니다.',
        '같은 용량의 2개짜리 키트를 고르세요.'),
       ('W4', 20, '이 CPU 의 오버클럭 기능을 이 보드에서 쓸 수 없습니다.',
        'CPU 오버클럭을 지원하는 칩셋의 보드나 오버클럭 불가 CPU 를 고르세요.'),
       ('W5', 20, 'CPU 의 TDP 가 보드 칩셋이 상정하는 값보다 높아 성능이 제한될 수 있습니다.',
        '상위 칩셋의 보드를 고르세요.');
```

#### 부품 쌍 단위 경고 뷰

W1, W3, W4, W5는 부품 두 개 사이의 규칙이라 견적 없이 부품 쌍 단위로 계산할 수 있다. W2는 담는 수량에
따라 달라지지만, 4개짜리 키트 하나는 수량과 관계없이 4 DIMM이므로 쌍 단위로 판정한다.

```sql
-- CPU × 보드 (W4, W5). 소켓이 맞는 쌍(B1 통과)만 대상
CREATE VIEW v_cpu_board_warnings AS
SELECT c.module_id AS cpu_id, mb.module_id AS board_id, 'W4' AS warning_code
FROM cpus c
         JOIN main_boards mb ON mb.socket = c.socket
         JOIN chipsets ch ON ch.chipset = mb.chipset
WHERE c.overclockable = 1
  AND ch.supports_cpu_oc = 0
UNION ALL
SELECT c.module_id, mb.module_id, 'W5'
FROM cpus c
         JOIN main_boards mb ON mb.socket = c.socket
         JOIN chipsets ch ON ch.chipset = mb.chipset
WHERE ch.rated_cpu_tdp_watt IS NOT NULL
  AND c.tdp_watt > ch.rated_cpu_tdp_watt;

-- CPU × 램 (W1, W2, W3). 키트 하나를 담는다고 가정한다.
-- cpu_memory_clocks 에는 CPU 가 지원하는 규격만 있으므로 조인 자체가 규격 호환을 보장한다.
CREATE VIEW v_cpu_ram_warnings AS
-- W1: 모듈 2개 이하 키트의 클럭 > CPU 공식 지원 클럭 (2 DIMM)
SELECT cm.cpu_id, r.module_id AS ram_id, 'W1' AS warning_code
FROM rams r
         JOIN cpu_memory_clocks cm ON cm.memory_spec = r.memory_spec
WHERE r.package_count <= 2
  AND r.clock > cm.max_clock_2dimm
UNION ALL
-- W2: 모듈 3개 이상 키트의 클럭 > CPU 공식 지원 클럭 (4 DIMM)
SELECT cm.cpu_id, r.module_id, 'W2'
FROM rams r
         JOIN cpu_memory_clocks cm ON cm.memory_spec = r.memory_spec
WHERE r.package_count > 2
  AND r.clock > cm.max_clock_4dimm
UNION ALL
-- W3: 모듈 1개짜리 키트 → 하나만 담으면 싱글 채널
SELECT cm.cpu_id, r.module_id, 'W3'
FROM rams r
         JOIN cpu_memory_clocks cm ON cm.memory_spec = r.memory_spec
WHERE r.package_count = 1;
```

#### 정렬 쿼리 예

"라이젠5 7500F와 호환되는 메인보드"처럼 이미 고른 부품이 있을 때 후보를 고르는 쿼리다. 하드 규칙은
`WHERE`/`JOIN`으로 거르고, 경고는 벌점 합계로 정렬한다.

```sql
-- 이 CPU 와 함께 쓸 메인보드: 경고 없는 보드가 먼저, 같은 벌점이면 싼 순
SELECT m.*,
       COALESCE(SUM(w.penalty), 0)       AS penalty,
       GROUP_CONCAT(v.warning_code)      AS warning_codes
FROM cpus c
         JOIN main_boards mb ON mb.socket = c.socket                  -- B1
         JOIN modules m ON m.module_id = mb.module_id
         LEFT JOIN v_cpu_board_warnings v ON v.cpu_id = c.module_id AND v.board_id = mb.module_id
         LEFT JOIN warning_rules w ON w.warning_code = v.warning_code
WHERE c.module_id = ?
GROUP BY m.module_id
ORDER BY penalty, m.price;

-- 이 CPU 와 함께 쓸 램: 경고 없는 램이 먼저, 같은 벌점이면 성능 높은 순
SELECT m.*,
       COALESCE(SUM(w.penalty), 0)       AS penalty,
       GROUP_CONCAT(v.warning_code)      AS warning_codes
FROM cpu_memory_clocks cm
         JOIN rams r ON r.memory_spec = cm.memory_spec                -- CPU 가 지원하는 규격만
         JOIN modules m ON m.module_id = r.module_id
         LEFT JOIN v_cpu_ram_warnings v ON v.cpu_id = cm.cpu_id AND v.ram_id = r.module_id
         LEFT JOIN warning_rules w ON w.warning_code = v.warning_code
WHERE cm.cpu_id = ?
GROUP BY m.module_id
ORDER BY penalty, m.performance_score DESC;
```

- `GROUP BY m.module_id`에서 `m.*`를 SELECT할 수 있는 이유는 `module_id`가 `modules`의 PK라서 나머지
  컬럼이 함수적으로 종속되기 때문이다(`ONLY_FULL_GROUP_BY`에서도 허용).
- 보드를 이미 골랐다면 램 쿼리에 `v_ram_board_compat`(4-3)를 조인해 B2·B3을 함께 거른다.
- 첫 번째 쿼리의 `JOIN main_boards mb ON mb.socket = c.socket`은 `v_cpu_board_compat`와 같은 조건이다.
  하드 규칙 필터를 한곳에서 관리하려면 4-3의 판별 뷰를 조인해 쓴다.
- 시드에서 7500F는 `overclockable = 1`이다. 첫 번째 쿼리에서 A620I AX는 W4 때문에 B650 보드 두 개보다
  뒤에 나온다(9-1에서 확인). 램 쿼리에서는 1개짜리 키트(삼성 DDR5-5600 16GB, SK하이닉스 DDR5-5600 32GB)가
  W3 때문에 2개짜리 키트보다 뒤에 나온다. DDR5-6000 키트는 W1이 붙지만 벌점이 0이라 순위는 그대로이고
  안내 문구만 붙는다.

#### 출력하는 곳별 적용

| 출력하는 곳 | 적용 방법 |
| --- | --- |
| NL2SQL 호환 부품 조회 ("○○와 호환되는 ××") | 4-3의 판별 뷰, 5-3의 경고 뷰, `warning_rules`를 [`schema_docs.json`](../../nl2sql/data/schema_docs.json)에 추가하고, 위 정렬 쿼리를 [`few_shot_examples.json`](../../nl2sql/data/few_shot_examples.json)에 예시로 넣는다. LLM이 같은 패턴(하드 규칙 필터 + 벌점 정렬)으로 SQL을 만들게 한다 |
| 추천 견적 | [ADR 0003](../adr/0003-decision-jev-for-unanswerable-questions.md)의 `recommendation` 판정에 해당한다. 조합을 만든 뒤 경고를 검사하고, 경고를 일으킨 부품을 쌍 단위 뷰에서 벌점이 가장 낮은 대안으로 바꾼다. 검증 노드처럼 최대 N회 반복하고, 끝까지 남은 경고는 "예산 안에 대안 없음" 같은 이유와 함께 출력한다 |
| 장바구니·견적 저장 | 5-2의 `v_build_warnings`를 `warning_rules`와 조인해 남은 경고를 노란 표시로 보여주고, `how_to_avoid` 문구로 바꿀 부품을 안내한다 |

- 수량을 고른 뒤에야 생기는 W2(2개짜리 키트를 2세트 담는 경우)는 쌍 단위 뷰로 알 수 없다. 추천할 때는
  "같은 총 용량이면 키트 하나를 우선한다"는 규칙으로 피하고, 저장한 견적에서는 `v_build_warnings`로 알린다.
- 벌점이 0인 경고(W1)도 출력할 때는 항상 문구를 보여준다. 정렬에 반영하지 않을 뿐 숨기지 않는다.

| 14세대 CPU + 600 시리즈 보드의 BIOS 업데이트 필요 여부 | 관련 데이터 없음 |

## 7. 값 제약 (V7)

부품 한 개의 숫자 스펙 검증이다. 컬럼별 제약은 2장의 부품별 표에 있다.

### 7-1. 적용 기준

- 원화 가격은 0 이상으로 허용한다. 무료 가격이 가능한 경우를 막지 않는다.
- 크기, 개수, 속도, 용량 등 실물 스펙은 양수여야 한다.
- HDD 버퍼 메모리만 0 이상으로 허용한다. 제공 데이터가 없을 때 0을 쓰는 기존 입력도 수용하고,
  음수만 차단한다. 0을 미확인 표시로 쓰지 않기로 결정하면 이후 마이그레이션에서 nullable 컬럼과
  데이터 정책을 함께 정리한다.
- `modules.performance_score`는 `NULL`을 허용하며, 값이 있으면 0 이상이어야 한다. MySQL `CHECK`는
  조건이 `UNKNOWN`인 경우를 허용하므로 이 제약은 NULL을 막지 않는다.
- `NOT NULL`은 V4 스키마에서 이미 적용되어 있다. 상세 수치를 알 수 없는 입력을 0으로 새로 저장하지
  말고, 입력 단계에서 보완하거나 별도 변경으로 nullable 정책을 결정한다.

### 7-2. 적용 전 확인

`CHECK` 제약은 기존 데이터에도 적용된다. 이미 저장된 행에 위반값이 있으면 마이그레이션이 실패하므로,
운영 DB에 적용하기 전 아래 조회 결과가 모두 0인지 확인한다.

```sql
SELECT 'modules.price' AS rule_name, COUNT(*) AS violations
FROM modules WHERE price < 0
UNION ALL
SELECT 'modules.performance_score', COUNT(*)
FROM modules WHERE performance_score < 0
UNION ALL
SELECT 'cpus.cores', COUNT(*) FROM cpus WHERE cores <= 0
UNION ALL
SELECT 'cpus.threads', COUNT(*) FROM cpus WHERE threads < cores
UNION ALL
SELECT 'main_boards.memory_slots', COUNT(*) FROM main_boards WHERE memory_slots <= 0
UNION ALL
SELECT 'rams.capacity', COUNT(*) FROM rams WHERE capacity <= 0
UNION ALL
SELECT 'rams.clock', COUNT(*) FROM rams WHERE clock <= 0
UNION ALL
SELECT 'rams.package_count', COUNT(*) FROM rams WHERE package_count <= 0
UNION ALL
SELECT 'graphic_cards.memory_capacity', COUNT(*) FROM graphic_cards WHERE memory_capacity <= 0
UNION ALL
SELECT 'graphic_cards.length_mm', COUNT(*) FROM graphic_cards WHERE length_mm <= 0
UNION ALL
SELECT 'graphic_cards.recommended_power', COUNT(*) FROM graphic_cards WHERE recommended_power <= 0
UNION ALL
SELECT 'power.rated_power', COUNT(*) FROM power WHERE rated_power <= 0
UNION ALL
SELECT 'ssds.capacity', COUNT(*) FROM ssds WHERE capacity <= 0
UNION ALL
SELECT 'ssds.read_speed', COUNT(*) FROM ssds WHERE read_speed <= 0
UNION ALL
SELECT 'ssds.write_speed', COUNT(*) FROM ssds WHERE write_speed <= 0
UNION ALL
SELECT 'hdds.capacity', COUNT(*) FROM hdds WHERE capacity <= 0
UNION ALL
SELECT 'hdds.rpm', COUNT(*) FROM hdds WHERE rpm <= 0
UNION ALL
SELECT 'hdds.buffer_memory', COUNT(*) FROM hdds WHERE buffer_memory < 0
UNION ALL
SELECT 'monitors.screen_size', COUNT(*) FROM monitors WHERE screen_size <= 0

SELECT 'monitors.refresh_rate', COUNT(*) FROM monitors WHERE refresh_rate <= 0;
```

위반값이 있으면 원본 제품 정보를 확인해 먼저 정정한다. 값을 임의로 0이나 양수로 치환하면 실제 스펙이
왜곡될 수 있다.

## 8. 결정 사항

| # | 결정 사항 | 결정 | 이유 |
| --- | --- | --- | --- |
| 1 | B를 어떤 방식으로 걸까 | 선택지 1 (`builds` + 복합 FK + `CHECK`) | 트리거 없이 선언적으로 보장된다 |
| 2 | 견적 저장 테이블을 이번 마이그레이션에 함께 만들까 | 포함 (`builds`, `build_storages`) | 강제(B)와 저장된 견적의 경고(`v_build_warnings`)에 필요하다 |
| 3 | 마이그레이션을 어떻게 나눌까 | 값 제약과 A·B·W를 V7 하나로 묶음 | V7이 아직 커밋 전이라 다음 번호로 나눌 필요가 없다 |
| 4 | 이번 범위에 어디까지 넣을까 | B1~B9, W1~W5 | W6은 단자 정규화까지 필요해 제외 |
| 5 | 경고 벌점 값 (5-3) | W1 0(안내만), W3 30, W2·W4·W5 20 | W1은 피하려면 더 느린 램을 골라야 한다. 나머지는 시작값이고 추천 결과를 보며 조정한다 |

## 9. 적용 결과와 다음 과제

### 9-1. MySQL 8.4 검증

docker compose와 같은 설정(`mysql:8.4`, `utf8mb4_unicode_ci`)의 빈 DB에 V1~V7을 적용하고 새 시드를 넣어
확인했다.

| 확인 항목 | 결과 |
| --- | --- |
| 기존 시드(48개)가 있는 DB에 V7 적용 | 오류 없음. 기존 값이 A의 조회 테이블 범위 안에 있다 |
| 빈 DB에 V1~V7 + 새 시드 | 1,200개 오류 없이 입력. 기존 48개는 이름·가격·점수 그대로 |
| 복합 FK에 NULL이 섞인 행 | 부모 검사를 건너뛴다. 부모에 없는 `(999, NULL)`이 들어갔다 (4-4 주의할 점 1) |
| 통과해야 하는 견적 4개 | 저장됨. 경고: 7500F + A620 + DDR5-6000 → W1·W4, 램 1개 → W3, 14900K + 32Gx2 키트 2세트 → W2 |
| B1~B9 위반 견적 | 모두 거부. 오류 메시지에 `ck_builds_b1_socket` 같은 제약 이름이 나온다 |
| `cpu_id`만 넣고 스펙을 비움 | `ck_builds_cpu_pair`로 거부 |
| 인텔 CPU의 소켓을 AM5로 위조 | `fk_builds_cpu`로 거부 |
| 견적에 담긴 부품 삭제 | `fk_builds_cpu`로 거부 (RESTRICT) |
| AM5 + DDR4 보드, B650 + LGA1700 보드, 소켓 오타 `LGA 1700` | 각각 `fk_main_boards_socket_memory_spec`, `fk_main_boards_chipset_socket`, `fk_cpus_socket`으로 거부 |
| 5-3 정렬 예 (7500F와 함께 쓸 보드) | B650M Pro RS, B650 토마호크(벌점 0) 다음에 A620I AX(W4, 벌점 20) |

시드 기준 판별 뷰 행 수는 CPU×보드 8,556, 램×보드 11,807, 그래픽카드×파워 18,609쌍이다. B7(커넥터)만
위반하는 그래픽카드×파워 쌍이 20개, B8(최대 용량)만 위반하는 램×보드 쌍이 7개 있어 테스트에 쓸 수 있다.

### 9-2. 로컬 DB 다시 만들기

V7 내용이 바뀌었으므로, 이전 V7을 이미 적용한 DB는 Flyway 체크섬 검증에서 실패한다. 시드도 다시 넣으면
같은 제품이 중복되므로 DB를 새로 만든다. **볼륨을 지우면 그 DB의 데이터(가입한 사용자 등)도 모두 지워진다.**

```bash
docker compose down -v          # mysql-data 볼륨 삭제
docker compose up -d mysql      # 빈 DB
docker compose up -d backend    # 기동하면서 Flyway 가 V1~V7 적용
docker compose exec -T mysql mysql -uapp -papp --default-character-set=utf8mb4 data_base_design \
  < backend/src/main/resources/db/seed/dummy_modules.sql
```

### 9-3. 다음 과제

- **부품 등록 API**: `GraphicCard`, `Power`, `MainBoard`, `CPU` 엔티티와 요청 DTO에 V7 컬럼(커넥터, 최대 메모리,
  영상 출력, TDP, 배수 해제)이 없다. `ddl-auto: validate`는 통과하지만, API로 등록한 부품은 커넥터 값이 0이고
  나머지는 NULL이다. `cpu_memory_clocks`를 등록하는 API도 없다.
- **견적 API**: `builds`에 스펙을 복사해 저장하는 서비스가 없다. 위반 시 MySQL 오류 3819(`CHECK`)·1452(FK)의
  제약 이름을 프론트 메시지로 바꾸는 처리도 필요하다.
- **부품 삭제**: 견적에 담긴 부품을 삭제하면 FK 오류가 난다. 지금 서비스는 이 오류를 따로 처리하지 않는다.
- **NL2SQL**: 판별 뷰·경고 뷰·`warning_rules`를 [`schema_docs.json`](../../nl2sql/data/schema_docs.json)에 아직 넣지 않았다(5-3).
- **서브타입 정합성**: 상세 테이블의 `module_id`가 `modules.module_id`를 참조하는 FK는 V4에서 이미
  설정되어 있다. 하지만 `cpus` 행의 부모 모듈이 실제로 CPU 카테고리인지, 모든 모듈이 정확히 한 상세
  테이블에만 존재하는지는 보장하지 않는다. `builds`는 상세 테이블을 직접 참조하므로 카테고리가 섞일 수
  없지만, `build_storages`는 `modules`를 참조하므로 저장장치가 아닌 부품이 들어갈 수 있다.
- **API 입력 검증**: DTO/서비스 검증은 잘못된 요청을 빨리 거절하는 용도이고 DB 제약을 대체하지 않는다.
- **6장 C 항목**: 케이스 카테고리, 보드 슬롯·포트 컬럼, 모니터·GPU 단자 정규화가 추가되면 B나 W로 옮긴다.
