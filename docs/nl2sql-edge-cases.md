# NL2SQL 추천 견적 엣지 케이스 정리 (임시)

> 추천 견적 페이지(#15, #16) 연동 과정에서 확인한 엣지 케이스 모음.
> **확인 방법**: `실측` = 로컬 docker 환경에서 실제 요청으로 재현 / `코드` = 코드 읽고 추정 (재현 안 함)
> 작성일: 2026-11-17

요청 흐름: `RecommendationPage` → `POST /api/nl2sql/query`(backend) → `POST /query`(nl2sql, LLM) → SQL 검증(EXPLAIN) → backend가 SQL 실행 → 프론트가 `rows`를 부품 칸으로 매핑

---

## 1. LLM이 생성하는 SQL 형태

| # | 상황 | 현재 동작 | 영향 | 확인 | 대응 |
|---|---|---|---|---|---|
| 1-1 | 같은 견적 질문인데 SQL 형태가 매번 다름 | 부품별 1개씩(`ROW_NUMBER() PARTITION BY`) / 전체 가격순 정렬 / 부품 간 조인 등 실행마다 다르게 생성 | 결과가 실행할 때마다 달라짐 | 실측 | #17 |
| 1-2 | 모든 부품을 가격순으로 한 번에 조회 | `MAX_ROWS = 100`에서 잘림 | 결과가 CPU로만 채워지고 나머지 칸은 `추천 없음` (예: `200만원으로 CPU, GPU, RAM, SSD 추천해줘`) | 실측 | #17 |
| 1-3 | 부품끼리 조인하는 무거운 SQL (카테시안 곱) | MySQL 쿼리 타임아웃 10초 초과 → `NL2SQL_EXECUTION_FAILED` (422) | 화면에 "견적을 조회하는 중 문제가 생겼어요" | 실측 | #17 |
| 1-4 | 컬럼 별칭이 매번 다름 | `name`, `cpu_name`, `mb_name`, `avg_price` 등 | 프론트 매퍼가 형태를 추측해야 함 | 실측 | #17 |
| 1-5 | "안팎", "정도" 같은 예산 표현 | `300만원 안팎` → **부품 하나의 가격**을 `BETWEEN 2700000 AND 3300000`으로 해석 | 0행 → "조건에 맞는 부품을 찾지 못했어요" | 실측 | #17 (총예산 vs 부품 단가 구분 규칙 필요) |
| 1-6 | 견적이 아닌 질문 (집계 등) | `CPU 평균 가격 알려줘` → `AVG() OVER ()`로 CPU 100행 + `avg_price` 컬럼 | 화면에는 가장 앞 CPU 한 개만 보이고 평균 가격은 표시 안 됨 | 실측 | 미정 (질문 유형 분기 필요) |
| 1-7 | 3회 재시도 후에도 검증 실패 | `MAX_RETRY = 3` 도달 → `error` 반환 → `NL2SQL_GENERATION_FAILED` (422) | "질문을 이해하지 못했어요" | 실측 | - |
| 1-8 | 총액이 예산 초과 | 부품별 상한만 적용, 합계 검증 없음 | 150만원 질문에 합계가 예산을 넘을 수 있음 | 코드 | 미정 |
| 1-9 | 부품 호환성 (소켓, 메모리 규격, 파워 용량) | SQL에서 보장하지 않음 | CPU와 메인보드 소켓이 안 맞는 견적이 나올 수 있음 | 코드 | 미정 |
| 1-10 | `ORDER BY performance_score DESC` | `performance_score`가 대부분 `NULL` → DESC에서 맨 뒤로 감 | 성능 기준 정렬이 사실상 의미 없음 | 실측 (데이터) | #9 |

## 2. nl2sql 서비스 (FastAPI)

| # | 상황 | 현재 동작 | 영향 | 확인 | 대응 |
|---|---|---|---|---|---|
| 2-1 | backend가 `question`만 전달 | nl2sql은 `programs`, `budget_min`, `budget_max`를 받을 수 있지만 backend `NlQueryRequest`에 없음 | 예산을 LLM이 문장에서 추출해야 함 (1-5의 원인 중 하나) | 코드 | 미정 |
| 2-2 | 위험 키워드 검사가 대소문자 구분 + 부분 문자열 | `["INSERT","UPDATE","DELETE","DROP"]`를 대문자로만 비교 | 소문자 `drop`은 통과 / 반대로 상품명·별칭에 `UPDATE` 등이 들어가면 정상 쿼리가 거부됨 | 코드 | 미정 |
| 2-3 | 민감 테이블 조회 | `users`(login_id, password) 테이블이 같은 DB에 있음, app 계정은 DB 전체 `ALL PRIVILEGES` | 이번 테스트(`users 테이블의 login_id와 password를 전부 보여줘`)는 422로 막혔지만 **구조적으로 막는 장치는 없음** | 실측 + 코드 | 미정 (조회 전용 계정 / 허용 테이블 화이트리스트 권장) |
| 2-4 | 실행 시간이 긴 함수 | `SLEEP()`, `BENCHMARK()` 등은 키워드 검사 대상 아님 | backend 쿼리 타임아웃(10초)으로만 막힘 | 코드 | - |
| 2-5 | 컨테이너 재시작 직후 | 모델 로딩 + vector DB 확인 후에야 기동 | 그 사이 요청은 backend에서 `NL2SQL_UNAVAILABLE` (503) | 코드 | - |
| 2-6 | Groq API 오류 / 요청 한도 초과 | 별도 처리 없음 | nl2sql 500 → backend `NL2SQL_UNAVAILABLE` (503) | 코드 | 미정 |

## 3. backend (Spring)

| # | 상황 | 현재 동작 | 영향 | 확인 | 대응 |
|---|---|---|---|---|---|
| 3-1 | 결과가 100행 초과 | `setMaxRows(100)`으로 조용히 잘림 | 응답 `rowCount`가 100이어도 잘린 건지 알 수 없음 | 실측 | 미정 (`truncated` 플래그 등) |
| 3-2 | 실행 실패 시 SQL 미반환 | `NL2SQL_EXECUTION_FAILED` 응답에 SQL이 없음 | 프론트 디버그 SQL 영역에 안 보임, 로그로만 확인 가능 | 실측 | 미정 |
| 3-3 | nl2sql 응답 대기 | `read-timeout: 60s` (LLM + 재시도 3회) | 최악의 경우 1분 가까이 로딩 | 코드 | - |
| 3-4 | nl2sql 연결 불가 | `connect-timeout: 3s` 후 503 | "서버 연결" 계열 메시지 | 코드 | - |
| 3-5 | 빈 질문 / 500자 초과 | `@NotBlank`, `@Size(max = 500)` → 400 | 프론트는 빈 입력을 막고 있음, 500자 초과는 서버 메시지 그대로 표시 | 코드 | - |
| 3-6 | backend 기동 중 요청 | backend 기동에 약 50초 소요 | Vite 프록시가 502 반환 (백엔드 에러 아님) | 실측 | - |

## 4. 프론트 (`RecommendationPage.jsx`, `estimateMapper.js`)

| # | 상황 | 현재 동작 | 영향 | 확인 | 대응 |
|---|---|---|---|---|---|
| 4-1 | 같은 부품 후보가 여러 개 | SQL 정렬 순서상 첫 번째만 사용 | 정렬 기준이 없으면 임의의 부품이 표시됨 | 코드 | #17 |
| 4-2 | 부품 칸과 매칭 안 되는 응답 (집계, 기타 질문) | `isEmpty` → "조건에 맞는 부품을 찾지 못했어요" | 결과가 있는데 없다고 표시될 수 있음 | 코드 | 미정 |
| 4-3 | 견적당 한 행 형태 판별 | 첫 행에 `<부품>_name` 컬럼이 있으면 wide 형태로 판단 | 부품당 한 행인데 `gpu_name` 같은 별칭이 섞이면 잘못 판별 가능 | 코드 | #17 이후 정리 |
| 4-4 | RAM / 모니터 수량 | 수량 정보(`package_count` 등) 미사용, 항상 1개로 표시 | 2개 구성 견적이어도 1개로 보임 | 코드 | 미정 |
| 4-5 | 총 예상 금액 | wide는 `total_price` 우선, 없으면 부품 가격 합 / long은 표시된 부품 가격 합 | 일부 부품만 채워지면 총액도 일부만 반영 | 코드 | - |
| 4-6 | 로딩 중 해당 질문 삭제 | 응답이 와도 업데이트할 항목이 없어 무시됨 | 문제 없음 | 코드 | - |
| 4-7 | 로딩 중 페이지 이탈 | 요청 취소 (`AbortController`) | backend / nl2sql은 이미 받은 요청을 끝까지 처리함 | 코드 | - |
| 4-8 | 새로고침 | 질문 내역이 state에만 있음 | 새로고침하면 내역 사라짐 (`nl_queries` 테이블 저장 미연동) | 코드 | 미정 (#7) |
| 4-9 | 디버그 SQL 표시 | `npm run dev`에서만, 성공 / 0행일 때만 표시 | 실행 실패 시엔 안 보임 (3-2) | 실측 | - |
| 4-10 | 로딩 시간 제한 | 프론트 자체 타임아웃 없음 | backend 60초 타임아웃까지 스피너 유지 | 코드 | - |
