개발 중 겪은 문제의 증상, 원인 분석, 해결 과정을 남긴다. 같은 문제를 다시 만났을 때 처음부터 조사하지 않도록 하는 것이 목적이다.

## 작성 방법

파일 하나에 문제 하나를 적는다. 파일 이름은 `영역-문제-요약.md` 형식의 영어 소문자로 짓고, 위 목록에 한 줄을 추가한다.

문서에는 다음 항목을 넣는다.

1. **증상**: 사용자 입장에서 무엇이 보였는지
2. **재현**: 같은 문제를 다시 일으키는 요청이나 절차
3. **배제한 원인**: 의심했지만 아니었던 것과 확인 방법
4. **원인 분석**: 왜 이런 일이 생기는지 단계별로
5. **해결**: 무엇을 바꿨는지, 아직 안 했다면 해결 방향
6. **확인 방법**: 고쳐졌는지 다시 확인하는 명령이나 쿼리

간단한 환경 설정 문제(Docker 포트 충돌 등)는 [CONTRIBUTING.md](../CONTRIBUTING.md)의 "문제 해결"에 적는다.
