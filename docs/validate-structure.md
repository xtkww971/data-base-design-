## 입력, 결과 값 검증

### 1. 입력 값 검증

LLM이 자연어 질의를 입력 받고 SQL 쿼리문을 생성할 때 쿼리문의  정확도를 높이기 위해서는 모호하지 않은 입력 값이 필요하다. “좋은”, “비싼”, “많은”, “작은” 같은 형용사가 섞인 질의 보다는 구체적인 비용, 스펙을 제시해 주는 것이 LLM의 성능에 유리하다. 이에따라 사용자에게 질의를 입력 받을 때 구체적인 값을 받도록 입력 값을 제한할 필요가 있다.

### 1.1 frontend

- **자연어 질의 가이드 라인 제시:**

사용자가 자연어 질의를 입력할 때 구체적인 스펙을 입력하고 모호한 질문을 피할 수 있도록 자연어 질의문 가이드라인을 제시한다. 

- **입력값 길이 제한:**

입력 값이 너무 길어지면 LLM의 토큰이 과소비 되므로 적당한 길이로 제한한다.

### 1.2 LLM

- **질의문 유형별 구분**

자연어를 질의를 여러 유형별로 분류하여 유형에 맞는 프롬프트를 추가하여 쿼리문의 정확도를 높인다.

- **질의문 유효성 판단:**

자연어 질의를 통해 쿼리문을 생성할 때 질의가 DB와 관련된 질의인지(컴퓨터 부품과 상관없는 자연어 질의 인지 고려) 판단한다.

### 1.3 backend

- **입력값 전처리:**

동의어(램/메모리), 오타 발생이 쉬운 단어(그래픽/그레픽, 메인보드/매인보드), 영어↔ 한글(램→ RAM) 등을 전처리를 통해 통일시켜서 정확성을 높인다.

- **개인정보를 묻는 질의 차단:**

유저의 개인정보를 묻는 질의가 들어오면 차단한다.

- **인젝션 위한 자연어 질의 차단:**

DB조작이나 보안이 필요한 정보에 대한 접근이 감지되면 차단한다.

### 2. 결과 값 검증

결과값은 실행할 때 오류가 없어야 하며 DB를 조작하는 쿼리문이 아니어야 한다. LangGraph 프레임워크의 이점인 순환구조를 사용하여 검증->재생성 구조를 만들어 최종 쿼리문에 대한 신뢰도와 정확도를 높여야 한다.

### 2.1 LLM

- **db 조작 쿼리 포함 되어 있는지 검증:**

"INSERT","UPDATE","DELETE","DROP” 등 DB를 조작하는 쿼리가 생성되거나 “SELECT”, “WITH”으로 시작하지 않는 쿼리문이 생성되면 쿼리를 재생성 한다.

- **db연결 후 모의 실행 후 오류 없는지 검증:**

EXPLAIN으로 쿼리를 미리 실행 후 오류가 있는지 검증하고 오류가 있을 경우 쿼리를 재생성 한다.(실제 있는 스키마 사용했는지 검증)

### 2.2 backend

- **쿼리 실행 시 output이 존재하는 지 검증:**

쿼리를 실행했을 때 오류는 없지만 DB에 쿼리와 관련된 데이터셋이 존재하지 않아 output이 없는 경우 LLM이 쿼리를 재생성 할 수 있도록 한다.
